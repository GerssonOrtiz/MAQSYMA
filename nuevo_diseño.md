# MAQSYMA 2.0 — REDISEÑO INTEGRAL

## ROL

Actúa como un equipo profesional compuesto por:

- Director de arte digital.
- Diseñador UX/UI senior.
- Diseñador web especializado en marcas industriales.
- Frontend developer senior.
- Especialista en motion design y experiencias cinematográficas.
- Especialista en conversión y ecommerce.

Tu objetivo NO es mejorar ligeramente la página existente.

Tu objetivo es **REDISEÑAR COMPLETAMENTE MAQSYMA**.

El resultado debe parecer una nueva versión de la marca y de la experiencia web.

---

# 1. REGLA PRINCIPAL

## NO HAGAS UN SIMPLE REDISEÑO DE SECCIONES

No quiero:

- cambiar colores y mantener la misma estructura;
- agregar un catálogo arriba;
- conservar el mismo orden de bloques;
- convertir la página actual en un ecommerce genérico;
- simplemente modificar textos;
- agregar más cards;
- hacer una versión ligeramente más bonita de la página existente.

Quiero una **experiencia web completamente nueva**.

Puedes:

- eliminar componentes;
- eliminar secciones;
- reorganizar completamente el contenido;
- reemplazar componentes;
- crear nuevos componentes;
- modificar la navegación;
- cambiar la estructura de la página;
- cambiar el sistema visual;
- cambiar la composición del hero;
- modificar completamente las animaciones;
- cambiar la forma de presentar los productos;
- crear nuevas interacciones;
- crear nuevas páginas.

No tienes que respetar la arquitectura visual actual si existe una solución mejor.

**El código existente es material de trabajo, no una restricción de diseño.**

# 5. NUEVA ARQUITECTURA DE LA HOME

No copies la estructura actual.

Diseña una nueva narrativa.

Una posible dirección conceptual es:

## 01 — IMPACTO

Hero cinematográfico.

No comenzar con:

> "Bienvenido a MAQSYMA"

Ni con un bloque comercial tradicional.

La primera pantalla debe generar impacto.

Debe comunicar inmediatamente:

**MAQSYMA**

**EQUIPAMIENTO PARA SOLDADURA Y CORTE INDUSTRIAL**

Utilizar:

- video;
- fotografía industrial;
- movimiento;
- iluminación;
- profundidad;
- elementos tipográficos grandes.

Debe existir un CTA claro hacia productos.

Ejemplo conceptual:

**EXPLORA LOS EQUIPOS**

y un segundo CTA:

**HABLA CON MAQSYMA**

---

# 6. HERO CINEMATOGRÁFICO

Rediseñar completamente el Hero actual.

No utilizar simplemente la estructura existente.

El hero debe sentirse como una escena cinematográfica.

Conceptualmente:

Un entorno industrial oscuro.

Una máquina de soldar como protagonista.

Iluminación lateral intensa.

Chispas.

Metal.

Soldadura.

Humo ligero.

Reflejos.

Profundidad.

Movimiento de cámara.

La máquina debe integrarse visualmente en la escena.

El texto debe ocupar una parte importante de la composición.

Evitar cubrir completamente la imagen con overlays negros.

El producto/escena debe seguir siendo visible.

---

# 7. TRANSICIÓN DESPUÉS DEL HERO

No colocar inmediatamente un grid de productos.

Crear una transición narrativa.

Por ejemplo:

> "La industria exige equipos que respondan."

Después:

**Soldadura. Corte. Potencia. Precisión.**

Utilizar una composición editorial.

Puede incluir:

- estadísticas reales si existen;
- categorías;
- palabras gigantes;
- fotografías;
- pequeñas especificaciones;
- movimiento horizontal;
- transición cinematográfica.

No inventar estadísticas.

---

# 8. SISTEMA DE CATEGORÍAS

Las categorías deben convertirse en una parte importante de la experiencia.

No utilizar simplemente:

```text
[Card]
[Card]
[Card]
[Card]
```

Diseñar una experiencia visual.

Por ejemplo:

**ENCUENTRA TU EQUIPO**

con categorías grandes:

- SOLDADURA
- CORTE Y PLASMA
- EPP
- ANTORCHAS
- ALIMENTADORES
- ACCESORIOS
- CONSUMIBLES

Cada categoría puede utilizar:

- fotografía;
- video corto;
- hover;
- movimiento;
- transición;
- composición editorial.

El usuario debe poder entrar directamente a la categoría.

---

# 9. PRODUCTOS DESTACADOS

Los productos no deben aparecer como un catálogo aburrido.

No crear una secuencia interminable de productos.

Crear una presentación editorial.

Ejemplo conceptual:

## EQUIPOS QUE MUEVEN EL TRABAJO

Un producto principal de gran tamaño.

Al lado:

- modelo;
- proceso;
- potencia;
- descripción breve;
- CTA.

Después otros productos secundarios.

Utilizar composición asimétrica.

Combinar:

- producto grande;
- producto pequeño;
- información técnica;
- fotografía;
- espacios vacíos.

---

# 10. PRODUCTOS

Crear un sistema moderno de catálogo.

Debe permitir explorar productos de forma intuitiva.

Filtros potenciales:

- categoría;
- proceso;
- marca;
- aplicación;
- rango de potencia;
- disponibilidad.

Pero no inventar filtros para datos que no existen.

El sistema debe ser compatible con los datos reales de Supabase.

---

# 11. FICHA DE PRODUCTO

Rediseñar completamente las páginas:

`/equipos/[slug]`

La ficha debe sentirse como una página editorial de producto industrial.

No utilizar una ficha ecommerce genérica.

Debe incluir:

- fotografía principal;
- nombre;
- marca;
- modelo;
- descripción;
- especificaciones;
- aplicaciones;
- características;
- CTA de consulta;
- productos relacionados.

El producto debe ser visualmente protagonista.

---

# 12. EXPERIENCIA "INDUSTRIA"

La web debe transmitir sensación de industria.

No necesariamente mediante muchas secciones.

Puede utilizar:

- fotografías panorámicas;
- videos;
- desplazamientos horizontales;
- parallax;
- elementos técnicos;
- animaciones sutiles;
- transiciones;
- zoom de imágenes;
- composición editorial.

El usuario debe sentir que está recorriendo un entorno industrial.

---

# 13. ELIMINAR SERVICIO TÉCNICO

## IMPORTANTE

Eliminar completamente la sección:

**SERVICIO TÉCNICO**

No debe aparecer como:

- sección;
- card;
- CTA;
- menú;
- footer;
- navegación;
- página independiente.

No diseñar una sustitución equivalente.

La arquitectura comercial debe concentrarse en:

- productos;
- categorías;
- venta;
- alquiler;
- marcas;
- contacto.

---

# 14. VENTA Y ALQUILER

Crear una sección comercial específica.

Concepto:

**EQUIPOS PARA COMPRAR O ALQUILAR**

Debe explicar visualmente las dos opciones.

### COMPRA

Equipos para operación permanente.

### ALQUILER

Soluciones para proyectos temporales.

Utilizar composición visual diferente a las secciones de productos.

CTA:

**CONSULTAR DISPONIBILIDAD**

No inventar condiciones de alquiler.

---

# 15. MARCAS

Crear una sección de marcas.

La marca principal existente debe presentarse correctamente.

No inventar distribuidores, certificaciones ni relaciones comerciales.

Si existen datos reales en el proyecto, utilizarlos.

Si no existen, dejar preparada la estructura sin inventar información.

---

# 16. WHATSAPP

WhatsApp debe ser uno de los principales mecanismos de conversión.

No convertir la web en una página llena de botones.

Utilizar CTA estratégicamente:

- Hero.
- Productos.
- Alquiler.
- Contacto.

El CTA debe ser contextual.

Ejemplos:

**CONSULTAR EQUIPO**

**CONSULTAR DISPONIBILIDAD**

**HABLAR CON MAQSYMA**

---

# 17. NAVEGACIÓN

Crear una navegación completamente nueva.

Debe ser limpia y premium.

Posible estructura:

```text
MAQSYMA

PRODUCTOS
CATEGORÍAS
MARCAS
VENTA Y ALQUILER
NOSOTROS
CONTACTO

[WhatsApp]
```

No utilizar:

- Taller;
- Más vendidos;
- Mejor valorados;
- Nuevos modelos;

como navegación principal.

Esos conceptos pueden existir internamente si aportan valor, pero no deben dominar la navegación.

---

# 18. MOBILE

El diseño móvil NO debe ser simplemente el desktop reducido.

Crear una experiencia específica para mobile.

Prioridades:

- navegación sencilla;
- imágenes optimizadas;
- CTA WhatsApp;
- lectura rápida;
- botones grandes;
- buen contraste;
- animaciones ligeras;
- evitar videos pesados;
- evitar scroll excesivamente largo.

---

# 19. ANIMACIONES

Utilizar motion design profesional.

Las animaciones deben reforzar la experiencia.

Ejemplos:

- reveal de títulos;
- desplazamiento de imágenes;
- parallax;
- scale;
- máscaras;
- transiciones entre escenas;
- hover de productos;
- desplazamientos horizontales.

Evitar:

- animaciones constantes;
- rebotes;
- efectos innecesarios;
- elementos flotando sin propósito.

La animación debe sentirse **industrial y cinematográfica**, no de landing page genérica.

---

# 20. IMÁGENES

Eliminar visualmente la dependencia de:

`PLACEHOLDER TEMPORAL`

y cualquier imagen claramente provisional en la interfaz final.

No fabricar imágenes de productos que puedan inducir a error.

Cuando no exista una fotografía real adecuada:

- utilizar una composición neutra;
- dejar preparado el sistema para reemplazarla;
- utilizar recursos disponibles en el proyecto;
- no inventar especificaciones visuales del producto.

---

# 21. DATOS

No inventar:

- precios;
- stock;
- reviews;
- ratings;
- certificaciones;
- disponibilidad;
- características técnicas;
- testimonios;
- estadísticas.

Si los datos existentes son DEMO:

identificarlos y evitar mostrarlos como datos reales.

En producción pública no deben aparecer datos DEMO como si fueran reales.

---

# 22. SUPABASE

Mantener la integración con Supabase cuando corresponda.

No destruir innecesariamente:

- RLS;
- estructura de autenticación;
- consultas;
- modelos de datos.

Pero sí puedes modificar la arquitectura de datos si es necesario para soportar correctamente el nuevo catálogo.

Antes de modificar el schema:

1. estudiar el schema actual;
2. estudiar las consultas;
3. estudiar los componentes;
4. detectar dependencias;
5. proponer la migración mínima necesaria.

No romper seguridad existente.

---

# 23. ARQUITECTURA FRONTEND

Puedes reorganizar:

```text
src/components
src/app
src/lib
src/data
src/config
```

si mejora la arquitectura.

Crear componentes reutilizables.

Evitar componentes gigantes.

Evitar duplicación.

Utilizar nombres claros.

Mantener TypeScript correctamente tipado.

---

# 24. SEO

Implementar una arquitectura SEO sólida.

Incluir:

- metadata;
- títulos;
- descriptions;
- Open Graph;
- estructura semántica;
- headings correctos;
- URLs limpias;
- páginas de categorías;
- páginas de productos.

No utilizar keyword stuffing.

---

# 25. PERFORMANCE

La web debe ser visualmente espectacular pero rápida.

Priorizar:

- optimización de imágenes;
- lazy loading;
- code splitting;
- optimización de videos;
- evitar JavaScript innecesario;
- evitar animaciones costosas;
- responsive images.

No sacrificar rendimiento únicamente por efectos visuales.

---

# 26. ACCESIBILIDAD

Mantener:

- contraste suficiente;
- navegación por teclado;
- labels;
- alt text;
- focus states;
- botones accesibles;
- respeto por `prefers-reduced-motion`.
